# CLAUDE.md — wow-addon plugin

## Purpose & stack

A **Claude Code plugin** (not a WoW addon itself) that ships helpers for World of Warcraft addon development: standard-compliant scaffolding, compliance auditing, standards-reference revendoring and cross-repo learning harvesting (the two halves of the standards cycle), interface/version bumping, doc sync, test-battery running, automated-test recording, changeset finalization, pending-work triage, GitHub issue listing/creation, git diff/commit, a line-ending hook, and a WoW-specific review subagent. Everything here is **Markdown command/agent specs + one Bash hook script + JSON manifests** — there is no compiled code and no test suite.

Current version: **1.20.0** (in `.claude-plugin/plugin.json`).

**This repo ships nothing to the WoW client, so it pins LF** (Ka0s WoW Addon Standard,
`line-endings-§2`). Its root `.gitattributes` carries the non-client canonical body — `* text=auto
eol=lf`, `*.sh text eol=lf`, binaries marked `binary`. Write LF here. The `*.sh` carve-out is not
decorative in this repo: `scripts/normalize-eol.sh` is the hook Claude Code executes, and a shebang
followed by CRLF makes the kernel look for an interpreter literally named `bash\r`.

## Module/package map

- `.claude-plugin/plugin.json` — plugin manifest; **the single source of truth for the version**.
- `.claude-plugin/marketplace.json` — marketplace entry; carries a **mirror of the description** (no version field of its own).
- `commands/*.md` — 16 slash-command specs (`/wow-addon:<name>`), each also invocable as a Skill of the same name. Two of them (`review.md`, `standards-audit.md`) are thin **wrappers that dispatch to the subagent of the same name**; the other fourteen act directly.
- `agents/*.md` — 2 subagent specs: `review` (WoW-specific principal-level review → `docs/reviews/<date>/`; also fetches the standard to keep its own remediation compliant, but does **not** audit) and `standards-audit` (read-only compliance audit → `docs/audits/<date>/`).
- `hooks/hooks.json` + `scripts/normalize-eol.sh` — the line-ending-normalization hook. It normalizes a just-written file to whatever `.gitattributes` declares for it — **CRLF** or **LF** — and exits silently when nothing is declared (`line-endings-§2`). Renamed from `normalize-crlf.sh` when it gained the LF arm; the old name described half of it.
- `README.md` — user-facing docs. `LICENSE` — MIT.

## Entry points & lifecycle

Claude Code auto-discovers `commands/` and `agents/` by directory; there is no registration file listing them. A command file becomes live the moment it exists and the plugin is (re)loaded. `hooks/hooks.json` registers the `PostToolUse` hook. To activate changes in a session: **`/reload-plugins`** (no restart needed).

- **Command spec** = YAML frontmatter (`description`, `argument-hint`, `allowed-tools`) + a Markdown body that instructs the agent. `$ARGUMENTS` is the user's argument string.
- **Agent spec** = frontmatter (`name`, `description`, `tools`) + body. The `name` becomes `wow-addon:<name>` when dispatched.

## Configuration & env

None. No env vars, no config files, no persistent state. Some specs need external tools **on the machine of whoever runs them** (still not local plugin config): `standards-audit`, `new-addon` and `revendor-standards` fetch the external **[`WowAddonStandards`](https://github.com/tusharsaxena/WowAddonStandards)** repo at runtime (raw GitHub, needs network); `fetch-issues` and `add-issue` shell out to the **`gh`** CLI (must be installed and authenticated), and `pending-audit` uses it too but treats an absent/unauthenticated `gh` as a skipped sweep rather than a failure; `harvest-standards` is the exception — it runs *inside* the standards repo and reads it from the **working tree** (it is about to edit those files), while reading every sibling addon repo off local disk, so it needs no network but does need the collection checked out beside it; `run-tests` invokes whatever it finds — **luacheck** and a **Lua** interpreter — treating an absent tool as a skipped suite, not a failure; `standards-audit`, `bump-version` and `review` additionally shell out to **`lizard`** for the complexity report, and all three treat its absence as *not run / report is stale*, never as a failure or a fabricated number — `review` also re-runs `luacheck` and the addon's Lua suites for the same reason, with the same skip-don't-fabricate rule.

## Build / test / run

- **No build, no tests.** Validation is: `python3 -c "import json; ..."` on the two manifests, and a manual `/reload-plugins` to confirm the plugin loads (`Reloaded: … plugins · … skills · … agents · … hooks`).
- The line-ending hook script is Bash; there's no harness for it beyond running the flow that triggers `Write|Edit|MultiEdit` inside a repo that declares an `eol`. **Validate both arms** — the `crlf` arm needs a client-bound repo (any addon, or `LibKa0s`), and the `lf` arm is exercised inside **this** repo, which pins LF. A third case matters as much as either: a path with no declared `eol` must come back byte-identical.

## Conventions & hot zones (footguns)

- **Adding/removing a command or agent is a 4-touch change.** Keep these in sync or the docs drift:
  1. the `commands/*.md` or `agents/*.md` file,
  2. the README table (Commands / Subagents),
  3. **both** manifest descriptions (`plugin.json` + `marketplace.json`),
  4. the version in `plugin.json` (bump it).
- **Command wrappers for subagents** (`review`, `standards-audit`) are documented under **Subagents** in the README, not the Commands table — follow that taxonomy for any future wrapper.
- **Runtime-fetch specs** (`standards-audit`, `new-addon`, `revendor-standards`, and — for its guardrail only — `review`): fetch the playbook + standard with `curl -fsSL` (verbatim); WebFetch is a **lossy fallback only** — its summarizer mangles verbatim content. If the standard can't be resolved: `standards-audit`/`new-addon`/`revendor-standards` must **hard-stop** (their whole output is worthless without it), but `review` must **degrade gracefully** — it fetches the standard only to keep its own remediation compliant, so on failure it proceeds with the review and notes that the standards cross-check was skipped. Don't "fix" `review` to hard-stop.
- **Hard-code only the entry points; discover the rest by following links.** The standard is **split** — `standards/STANDARDS.md` is an index whose **Sections** list links one file per section under `standards/standards/`. Specs fetch `STANDARDS.md` and then **every section file it lists**; they **must not** hard-code section filenames, so the standard can be re-organized upstream without touching this plugin. The only fixed remote paths are the playbooks (`AUDIT.md`/`NEW_ADDON.md`), `standards/STANDARDS.md`, and `standards/NEW_ADDON_CONTEXT.md` (fetched verbatim at scaffold time and read from a scratch path — **never** written into an addon repo; a stored `docs/agent-context.md` is anti-pattern #49).
- **A Ka0s addon's root is three docs plus `LICENSE`** — the full `README.md`, the **stub** `CLAUDE.md`, and `DEPENDENCIES.md` (the toolchain contract: every dependency with the evidence for it, split runtime / development / release-and-assets, WSL2-Ubuntu install commands that actually work, one-line verification per tool). **Its `docs/` is the canonical trio** — `ARCHITECTURE.md`, `testing.md`, `smoke-tests.md` — **plus five verification-and-record docs** (the generated `test-cases.md`, `performance.md`, `perf-runs/README.md`, `automated-tests/README.md`, and the generated `automated-tests/RESULTS.md`) **plus the six unconditional Tier 1 topic-detail docs** (`scope.md`, `module-map.md`, `schema.md`, `settings-panel.md`, `data-flow.md`, `common-tasks.md`), with **Tier 2** (`slash-dispatch.md`, `midnight-quirks.md`, `compat-layer.md`, `message-bus.md`, `profiles.md`, `debug.md`) required per its stated trigger and otherwise recorded as a *Not applicable* row in `ARCHITECTURE.md`'s `## Documentation map`, and **Tier 3** addon-specific and free-form (documentation-§3). There is **no** `docs/complexity.md` (retired in standard v2.19.0), **no** `docs/file-index.md` or `docs/conventions.md` (retired v2.23.0), and **no** `docs/agent-context.md`; the root `CLAUDE.md` stub is the only agent brief in the repo. **Never state any of these counts without naming its members** — an unfilled slot is what makes a spec reconstruct a deleted file from memory.
- **Automated test records are recorded, and only two of the four suites gate.** The vendored `tests/_kit/run-automated-tests.sh` runs lint, the headless harness, the offline perf scenarios and `lizard`, writing a frozen bundle per run to `docs/automated-tests/<YYYYMMDD-HHMMSS>/` plus a row in `RESULTS.md` — **one** file overwritten in place so git history is the trend line. **`lint` and `tests` gate; `perf` and `complexity` never fail a run** — a threshold that fails a run teaches everyone to reach for `--no-verify`. A missing tool is a **skip recorded with its reason**, never a pass. A full bundle is produced at **release**, before the tag, and never gates a commit. `docs/complexity.md` was retired in standard v2.19.0.
- **A complexity number in Lua is not read the way it is elsewhere, and a disposition expires.** `lizard` counts every `and`/`or` short-circuit as a decision, so a run of `t.k = rec.k or D.k` defaulting lines scores CCN 13 with no visible branching — a high number usually means dense **defaulting/guarding**, not tangled control flow, and the fix is a module-level data table plus one loop rather than restructured logic. Any spec that writes a watch-list disposition must treat **Accepted** as having a shelf life: carried across three consecutive release runs, the entry is owed a fix or a tracked deviation ID (anti-pattern #53). And a refactor triggered by the report is itself constrained (`performance-§11`) — no body dumped into a nameless helper (#52), no dispatch table built inside the function it serves, no behavior change in a mechanical diff, and a characterization test **before** refactoring anything untested.
- **Two checkpoints, two different gates.** **Commits** are gated on lint + the headless harness only (`testing-§4`), and `perf`/`complexity` never fail a run — that rule is retained verbatim, and the vendored runner's exit code **MUST NOT** be changed to implement any threshold, because the same script is the commit gate. **Releases** are gated on all four suites plus **zero functions above CCN 15**, evaluated by `/wow-addon:bump-version` reading the run's `manifest.json` **before it edits anything** (`automated-tests-§3`, *The release gate*). A `skip` is not a pass: an unmeasured suite blocks the release as NOT EVALUATED. The asymmetry is the point — a commit gate is routed around with `--no-verify`; a release has no such hatch.
- **`docs/complexity.md` is retired (standard v2.19.0).** The raw report is each bundle's `complexity.txt`; the trend line and watch list are `docs/automated-tests/RESULTS.md`. No spec may scaffold, regenerate or sync a `docs/complexity.md` — finding one in an addon is a **pre-adoption finding to report**, never a doc to keep current.
- **`review` measures before it reviews, and only what runs outside the game.** Its Step 0 re-runs `luacheck`, the headless suite, a fresh `--list` inventory, `tests/perf.lua`, `lizard`, any `Makefile` `test` target, and the vendored-copy `diff` — because a committed artifact is a claim about a *past* state of the code, and the review is about the present one. Two boundaries hold it in place: **fresh output goes to scratch, never into the repo** (the inventory moves with the change that moves the pass count; the complexity report moves at release), and **anything needing a login is not run** — it is written up in `03_SMOKE_TESTS.md` for a human. A missing tool is a **stated skip**, never an inferred pass and never a silent fallback to the committed artifact. This is measurement in service of findings, not a gate: `run-tests` still owns running suites as a gate and offering to fix them, and `review` reports a red suite rather than fixing it mid-review.
- **Reference the standard's sections as `filename-§N`.** A whole section is its bare filename (`architecture`, `anti-patterns`); a subsection is `filename-§N` (`architecture-§5`, `documentation-§1`), the number being that section's **local** count. The old global `§N.M` notation is retired — don't use or reintroduce it in specs or artifacts.
- **Artifact directories in the target addon.** Three specs write dated or persistent artifacts into the addon they operate on, and each owns its own tree: `review` → `docs/reviews/<date>/`, `standards-audit` → `docs/audits/<date>/`, `pending-audit` → `docs/pending/LEDGER.md`. The dated bundles are **frozen history** — `pending-audit` reads their execution plans to find unexecuted rows but must never edit them. `LEDGER.md` is the opposite: long-lived and merged across runs, so a decision survives and isn't re-interviewed. Its four values are load-bearing — `done` and `wont-do` are **terminal** (the item is dropped entirely on later runs), `deferred` is a decided "not now" (collapsed to a count), and `untriaged` means the user was never asked (written by the inventory-only path and by an early stop), so it is **re-interviewed in full** and must never read as agreement. An item only re-opens if its evidence hash changes. A deferral can optionally file a GitHub issue; the row's `Issue` column then links the two, and the `ISS` item that comes back from the next `gh issue list` must be dropped in favor of the original row — otherwise the same work gets interviewed twice. Don't let `pending-audit` infer `wont-do` from silence or an early stop; only an explicit user choice closes something permanently. Each value is written **marker + word** (`🟢 done`, `🔵 wont-do`, `🟡 deferred`, `⚪ untriaged`) — the word is the data (greppable, screen-readable, emoji-font-independent) and the circle is only the affordance, so never write one without the other, never add a fifth marker, and never recolor an existing one.
- **Vendored folders in the target addon are read-only, and every spec that can edit code must say so.** Ka0s addons now vendor a shared library at `libs/LibKa0s/` (whole-folder, TOC-listed as its own aggregate `.xml`) and a shared headless test kit at `tests/_kit/` — a *sibling* of the library's ship folder, never under `libs/`. Both are copies. A defect in either is an **upstream** finding: fix it in the library repo, bump the file's LibStub minor, re-vendor the whole folder as its own commit in every consumer. A local patch is reverted silently by the next copy, and the behavior comes back as a regression with **no cause in the consumer's history** — which is why `review` reports these as `[upstream]` and `run-tests` refuses to patch under them even to turn a suite green. The corollary for `new-addon`: the shared subsystems (chat printer, debug console, options toolkit, slash dispatcher, perf harness, test framework) are **consumed, not written** — one setup file per adopted module, holding a **descriptor** plus a **degradation stub**, and nothing else. Don't let any spec drift back toward hand-building or local patching; anything genuinely missing goes upstream as an **additive** field.
- **The `LibKa0s` provenance line lives in the addon's root `CLAUDE.md`, not its `README.md`.** `Bundles [LibKa0s](https://github.com/tusharsaxena/LibKa0s) vX.Y.Z (MIT).` names the tag both vendored payloads (`libs/LibKa0s/` and `tests/_kit/`) were copied from, and it is the **input** to the consumer-side vendored-payload gate the addon runs as `tests/test_vendor_sync.lua` (`testing-§11`). It moved out of `README.md` at **LibKa0s v1.8.1 / test-kit revision 9**, and the gate has **no fallback**: a line left in the README reads to it as no line at all, and a **missing** line fails the case rather than skipping it (unlike an absent sibling checkout, which does skip). Four consequences bind specs here: `new-addon` writes the line into the `CLAUDE.md` stub it scaffolds; `sync-docs` **moves** one it finds in a README rather than refreshing it in place; `bump-version` must **never** roll that `vX.Y.Z` to the addon's new version — it is the library's tag, not the addon's; and `standards-audit` reads it to pick the tag it diffs the vendored copies against, instead of the sibling repo's `HEAD`. The line only moves on a re-vendor, in the **same commit** as the bytes, in both directions.
- **The addon README carries no bundled-library inventory, and its standard badge is not a link** (`documentation-§1`, anti-patterns #58/#59). No `## Libraries` / `## Bundled libraries` / `## Libraries and credits` / `## Credits and libraries` / `## Credits and bundled libraries` section, and no library roll-call smuggled into the intro paragraph — the Ace3/LibSharedMedia/LibDataBroker/LibDBIcon list, the "everything ships inside it, nothing else to install" prose and the `Bundles [LibKa0s] …` sentence all stay out, because a vendored-library list is a contributor fact with two homes that are actually read (`DEPENDENCIES.md`, `docs/ARCHITECTURE.md`) and the README is written for players. What survives is genuinely **external** credit only — a third-party artist, a font, a sound pack — as an optional `## Credits` section placed **last**, after `## Version History`; with nothing external to credit, the section does not exist. The standard badge is the bare `![Standard](https://img.shields.io/badge/Ka0s-WoW_Addon_Standard-yellow)` (`_`, not `%20`) and **MUST NOT** be re-wrapped in `[…](https://github.com/tusharsaxena/WowAddonStandards)` — the binding standards reference is the TOC `## X-Standard:` field and `CLAUDE.md`'s `## Standards compliance (read first)`; the badge declares, it does not navigate. No spec may scaffold, restore or "tidy up" either shape back into an addon.
- **`standards-audit` is read-only** on the audited addon — it only writes under `docs/audits/<date>/`. Don't let it edit addon code.
- **The standards cycle runs both ways, and the two halves must not blur.** `revendor-standards` runs **in an addon repo** and carries the standard **down**; `harvest-standards` runs **in the standards repo** and carries the collection's learnings **up**. The load-bearing asymmetry: `harvest-standards` is **read-only on every addon repo and on `LibKa0s`** — not politeness, but what keeps its evidence independent of its argument. If it edited as it swept, the next run would read its own text back as if it were nine repos agreeing. For the same reason neither command ever edits a frozen `docs/audits/` or `docs/reviews/` bundle: those are the harvest's primary source, and their value is that they record what was true against the standard of *their* date. Cross-repo synthesis is `harvest-standards`' whole reason to exist — every other spec here reads exactly one repo — so a run that only re-reads one repo has done nothing new.
- **The ripple is the dangerous part of a standards change, not the rule.** A rule edited in its section and missed in the index blurb, the anti-pattern range, `NEW_ADDON_CONTEXT.md`, `EXECUTIVE_SUMMARY.md` or a playbook leaves the standard **contradicting itself**, and the stale copy is what gets followed. Upstream has already spent a whole patch release cleaning up one incomplete ripple — a count still reading "quartet" beside three named members, which an agent completed from memory with the very file that release had deleted. `harvest-standards` owns that checklist and must discharge it item by item.
- **The quirks catalogue is the one piece of upstream text that *is* vendored into an addon.** Everything else about the standard is pointed at, never copied (#49) — but client quirks are reference data, not instructions, and an addon needs them next to the code that works around them. So they get the `libs/LibKa0s/` discipline instead: a marked block, copied **whole**, replaced **wholesale**, never patched locally, and **stamped with its source version** (a vendored copy without its version cannot be told stale from current — the same reason LibStub minors exist; this is the deliberate exception to "no standard version in a repo file", which governs the *reference*). Below the end marker is the addon's own section: `revendor-standards` must not touch it beyond pruning entries promoted upstream, because it is `harvest-standards`' input and editing it would let one command launder its own text into the other's evidence.
- **Three specs touch the same doc set from different directions; keep the split.** `standards-audit` measures the addon *against* the standard and writes a frozen bundle (read-only, findings). `sync-docs` reconciles docs against the addon's **own code** — count claims, slash parity, dead exports, the comment-citation check, doc scaffolding, and the migrate-then-delete flow for `docs/agent-context.md`. `revendor-standards` reconciles docs against the **current upstream standard text** and edits in place — the three-place reference (`documentation-§6`), retired and unresolvable forms swept out of the **whole repo**, and gate claims the standard has since qualified. The boundary rule: anything needing code analysis is `sync-docs`'s, anything needing the fetched standard is `revendor-standards`'. Two consequences that look like gaps and are not — `revendor-standards` **flags** a missing `docs/` member or root `DEPENDENCIES.md` instead of creating it (an `ARCHITECTURE.md` written without reading the code, or a `DEPENDENCIES.md` written without the evidence, is worse than an absent one) and **reports** `docs/agent-context.md` instead of deleting it (two specs owning one destructive action is how the salvage half gets skipped). It also **must not** rewrite frozen `docs/audits/` or `docs/reviews/` bundles even when they use retired notation: they record what was true against the standard of *their* date, which is what a dated artifact is for. And "revendor" there means the **reference**, never a copy — storing the standard's text in an addon is the same failure as storing the context pack (#49).
- **Two specs may now touch a comment, and their edit boundary is one boundary written twice.** `revendor-standards`' 3b sweep corrects a citation of the **standard** sitting in a code or config comment; `sync-docs`' comment-citation check corrects a comment citing **this repo** — a path that is not there, a `:N` past the end of the file, a `Symbol.Member` with no definition and no call site. Both are a deliberate, narrow relaxation of "documentation only", and both are fenced on the same four sides: **that sweep/check only**, **comments only** (a string literal, a key or a value is reported, never edited), **explicit confirmation every time** (silence is a decline, not a default), and **never a guessed target** (the user names the replacement or the item stays flagged). The rule's purpose survives intact — an agent licensed to rewrite every repo's `CLAUDE.md` still cannot reach a line that runs. The two are written to match on purpose: **if they ever disagree, that is the bug**, and the fix is to bring them back into alignment rather than to let one drift wider. Widening what either command *reads* never widens what it may *write*, and neither may touch `libs/`, `Libs/` or `tests/_kit/` at all.
- **`finalize` is the only spec that pushes.** Every other git-touching spec here stops at the commit and reminds the user to push — `commit.md` says so as a hard rule. That rule stands; the finalizer overrides it deliberately and says so in its own body, because the ordering it exists to enforce (a vendored library must be **on origin** before a consumer whose docs cite it lands) is not expressible if pushing is somebody else's later step. Don't "fix" the inconsistency by teaching the other specs to push.
- **`finalize` establishes its scope before it acts, and never guesses it.** It covers both the one-repo and the many-repo case, so the scope is a decision, not a given. It proceeds unasked only when the answer is certain — explicit `$ARGUMENTS` (including `here`), exactly one dirty repo, or several linked by *hard* evidence (this session touched each, a vendored folder matches a changed sibling source, a changed file cites a sibling path that also changed). Anything else — unrelated-looking candidates, repos the session never touched, unaccountable dirt — prints per-candidate changes and asks. Too narrow strands half a changeset unpushed while the other half references it on origin; too wide commits someone's work-in-progress under a message that is then wrong for both, which no revert fixes. Don't let it collapse back into "multi-repo only" or into silently picking the likely scope.
- **Commit style:** terse capitalized imperative subjects, no Conventional-Commits prefix; releases commit **directly to `master`**; commits carry a `Co-Authored-By: Claude …` trailer (match the recent `git log`).
